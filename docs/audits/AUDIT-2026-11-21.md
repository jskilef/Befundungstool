## Confirmed defect

| ID | Priority | Finding | Location |
| --- | --- | --- | --- |
| B01 | **P1, fixed** | "Neuer Befund" keeps a pending transcript and a running recording; the transcript can then be inserted into the new report | `src/core/editor.js:127` (new-report handler), `src/speech/panel.js` |

**B01 — reproduced.**
- **Steps:** dictate into patient A's report and leave the transcript pending, then press "Neuer Befund" and confirm.
- **Result:**
  - The report is cleared, but the card "Diktat · noch nicht eingefügt" with A's text stays visible.
  - "Einfügen" puts A's text into the new, empty report.
  - A recording started before "Neuer Befund" keeps running (`aria-pressed="true"`), and would therefore transcribe audio from both reports into the new one.
- **Cause:** the new-report handler calls `aiPanel.clearResults()` but nothing in the speech panel.
- **Fix:**
  - The speech panel has a `clear()` that cancels the recording, aborts the transcription and discards the pending text. A session counter drops results that arrive after it. "Neuer Befund" calls it. The feature switch uses the same function.
  - An active dictation (recording, transcription or pending transcript) counts as unsaved work, so "Neuer Befund" asks first even when the report itself is empty.
  - Template changes need nothing extra: inserting into a section that is no longer visible is already refused.
  - Found while testing: cancelling a running transcription threw an error, because the code tried to zero the audio buffer after it had been handed to the worker. It now zeroes only buffers it still holds.
  - Regression test in `tests/ui/speech-ui.cjs`: a pending transcript, a running recording and a transcription held open by the test, each followed by "Neuer Befund". It fails on the old code and passes on the fix; the full suite on `main` passes (43/43).

## Risks and recommendations

| ID | Level | Topic | Evidence and suggestion |
| --- | --- | --- | --- |
| R1 | Medium | Runtime code from a CDN without integrity check | `src/ai/local.js`, `src/ai/gguf.js` and `src/speech/whisper.js` import Transformers.js 3.8.1/4.3.0, WebLLM 0.2.85 and wllama 3.8.1 from jsDelivr. The versions are pinned, but nothing checks a hash. In the launcher and desktop app this code runs in the app's origin, with access to report text, the `/api` session token and unlocked keys. ## Verified strengths

- **Desktop app (`desktop/main.cjs`, `desktop/policy.cjs`):**
  - Sandbox, context isolation and no Node integration.
  - Navigation stays in the app; only plain `https:` links open outside it.
  - Permissions are denied by default; only microphone (audio only) and clipboard writes are allowed.
  - `disable-background-networking`, no reload menu entry that could discard text, and one instance per data folder.
  - Electron fuses: `runAsNode` off and app loaded only from the asar archive.
  - A fixed port without silent fallback, so user data stays on the same origin.
- **Launcher (`server/local-server.cjs`):**
  - Host check against DNS rebinding.
  - Origin and session token compared in constant time.
  - JSON-only requests with a size limit; only `https:` or loopback targets.
  - A header allow-list.
  - Upstream error texts are never passed on, only known codes.
  - In the desktop app, requests go through Chromium's network stack, so system proxy and certificate settings apply.
- **AI safeguards:**
  - Strict answer checks, outdated-result tracking and frozen-text protection.
  - Imported AI connections need confirmation.
  - Clear "too long" handling.
  - All covered by tests.

## Checked and found fine (negative results)
