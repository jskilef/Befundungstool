# Befundungstool project audit — 15 November 2026

Audited version: **0.1.0**, commit **95176056bf63f9fa2b4352189f38209dfd8ad669**.

This was a read-only software audit. Only this report and its [verification companion](AUDIT-2026-11-15-VERIFICATION.md) were added to the project. Application code, existing documentation, dependencies, build output, and Git history were left unchanged. The two predecessor projects were not modified or executed.

## Assessment

The project has a useful foundation: isolated rule engines, a self-contained build, explicit application of AI suggestions, encrypted configuration, a restricted loopback proxy, and substantial regression coverage. **All 38 existing test scripts passed across the initial isolated run and environment-adjusted reruns.** All 16 local assets/license documents with recorded SHA-256 hashes matched their inventory.

Additional synthetic probes reproduced **nine defects**, including two high-priority problems: applying an AI suggestion without a stale-result warning after another section changes, and an automatic startup reload erasing an unsaved draft. A passing existing suite does not cover these cases.

I would fix the report-integrity and asynchronous-state issues before expanding the feature set. I would retain the standalone architecture, minimal dependencies, explicit transfer decisions, and German clinical-output rules.

Priorities below describe software/product impact, not a CVSS rating or a clinical certification assessment:

- **P1 — high:** address first; can lose report work or bypass an intended report-review safeguard.
- **P2 — moderate:** reproducible incorrect behavior, data-handling failure, or misleading UI in a narrower workflow.
- The later improvement list contains recommendations and source-review observations, separately from reproduced defects.

### A01 — Incomplete provenance check for applying AI suggestions

**Evidence:** `snapshot()` records the full input at `src/ai/panel.js:500`, and the notes use that snapshot. However, `sectionStale()` at line 515 checks only the target section's text, the template, and report language. `applySection()` at line 605 uses this narrower check. Changes to another section, provider, endpoint, model, prompt, or protected ranges are not all covered by that decision.

**Reproduction:** Generate a revision of the impression using findings A. Change only the findings to B. The notes correctly show “Veraltet”, but the impression suggestion still shows “Erstellt”. Applying it produces **zero confirmation dialogs** and replaces the impression with the suggestion based on A.

**Impact:** A suggestion derived from superseded clinical context can look current and pass through the stale-result safeguard. The model receives multiple sections precisely because their relationship matters.

**Suggested change:** Use the complete request provenance when deciding whether a suggestion is current. Distinguish unexpected clinician/input changes from deliberate application of another suggestion from the same result, so sequential application remains usable. Preserve the input snapshot and make the confirmation decision consistent between notes and cards.

**Regression checks:** Change findings while retaining an impression suggestion; change comparison/indication; change the model/prompt; change frozen ranges. Verify warnings and declined application preserve the report. Also verify applying several suggestions from one result works as intended.

### A02 — Startup isolation reload loses newly entered report text

**Evidence:** `enableIsolation()` registers `coi-sw.js` on eligible HTTPS pages without checking the selected provider, then calls `location.reload()` on activation (`src/core/storage-migration.js:19–25`). There is no dirty-report check or user handoff.

**Reproduction:** On a fresh HTTPS browser context, delay the worker script response. Keep AI off and draft saving off, type a synthetic finding, then allow worker installation to finish. After the page becomes cross-origin isolated, the finding is empty.

**Impact:** A normal first visit with a delayed worker installation can erase work. This also initiates an extra same-origin worker request with no AI provider selected, contrary to the stated no-background-network rule. The reproduction did **not** transmit report text to an AI service.

**Suggested change:** Initialize hosted isolation when browser inference actually needs it. Never automatically reload an editor containing unsaved work. Offer a deliberate reload/defer workflow and respect draft-saving opt-out; do not solve this by silently persisting report text. Keep the launcher's existing isolation headers.

**Regression checks:** Slow first installation with and without a draft; AI disabled; draft saving disabled; an existing controlling worker; repeated visits; worker-registration failure. Verify no lost text and no reload loop.

### A03 — GGUF load lifecycle has cancellation and model-identity races

**Evidence:** `ensureLoaded()` keeps the new runtime in a local variable until loading completes, then assigns `wllama` and derives `loadedKey` from the mutable current `file` (`src/ai/gguf.js:179–202`). `release()` only sees an already-assigned runtime. `stop()` and `setFile()` do not invalidate an in-progress load.

**Reproduced with an injected runtime whose load completion is controllable:**

- Abort during loading: the request rejects with `AbortError`, but the runner ends with `loaded === true` and the runtime's `exit()` was never called.
- Unload during loading: loading finishes and generation still returns a result.
- Change from file A to B during A's load: B is the selected file, but the next request still uses A; only one model load occurs.

**Impact:** Cancellation can leave substantial model resources alive, and the displayed model identity can disagree with the model actually used. These probes establish lifecycle behavior; they do not measure real-model memory consumption.

**Suggested change:** Capture an immutable file/load identity, use a generation counter or request ticket, and track the loading instance as well as the loaded instance. After every asynchronous boundary, reject obsolete work and dispose its instance. Unload, cancellation, and file/provider changes should invalidate pending work, with cleanup performed once.

**Regression checks:** Abort/stop/file change during import, splitting, model loading, and generation; rapid A→B→A selection; confirm obsolete instances exit and only the selected file can become current. Preserve the existing byte-exact shard tests.

### A04 — “Forget” can be undone by a pending vault write

**Evidence:** `save()` awaits encryption before writing to storage. `forget()` clears the session and removes the key, but does not invalidate those pending saves (`src/settings/vault.js:30–45`). The editor starts automatic saves on settings changes without awaiting them (`src/core/editor.js:333`).

**Reproduction using the real crypto implementation:** Create a vault; start `vault.save(updatedPayload)`; immediately call `vault.forget()`; await the save. Immediately after forgetting, `exists` is false. After the pending save finishes, `exists` is true again.

**Impact:** The user's explicit deletion of the encrypted browser copy is not durable. This is a retention/state-ordering defect; the demonstrated stored data remains encrypted.

**Suggested change:** Give the vault an operation generation and invalidate it on forget/lock/recreation. Serialize or version writes so outdated encryptions cannot commit. Reflect save failures in the vault status instead of silently leaving the automatic-save claim unchanged.

**Regression checks:** Forget during resealing and password-based creation, lock during unlock, overlapping updates, and password changes with an older save pending. The last authorized operation must determine stored state.

### A05 — The UI permits a library its own loader rejects

**Evidence:** `validTemplates()` limits the library to 100 templates (`src/settings/config.js:6`). The template save handler adds a new template without enforcing that count (`src/core/editor.js:99`). Startup accepts the saved library only if the whole library validates (`src/core/editor.js:101`). The 30-fields-per-template UI guard does exist and worked in testing.

**Reproduction:** Start with 100 valid synthetic templates, create one more through the ordinary template dialog, and reload. Before reload: 101 visible/saved templates, validation false. After reload: **zero custom templates in the UI**, while the original 101 remain in local storage.

**Impact:** The entire library becomes inaccessible. Saving another library later can overwrite the recoverable stored copy. Reports relying on those custom fields also lose their normal editing route.

**Suggested change:** Enforce the shared library limit before mutation, provide a clear limit message, and validate the complete next state before persisting it. On invalid stored data, preserve it and show a recovery/import path instead of silently appearing to have an empty library.

**Regression checks:** 99→100, 100→101, editing an existing template at the limit, reload after a rejected addition, and recovery of an invalid saved library.

### A06 — Legacy import silently truncates content

**Evidence:** `fromReportStudio()` accepts up to 200 source templates but maps only `slice(0, 100)` (`src/settings/unified.js:102–114`). `splitTemplateBody()` returns only `fields.slice(0, 30)` at line 93.

**Reproduction:** An otherwise valid synthetic Report Studio file with 101 templates parses successfully into 100. A template body with 31 headings parses into 30 fields. Neither operation reports the omitted content.

**Impact:** Migration can appear successful while losing library content, including default report wording. This conflicts with preserving legacy information for review.

**Suggested change:** Preflight limits and either reject the import with a clear, lossless explanation or provide an explicit review of omitted content. A documented overflow mapping is another option only if it preserves all text and the user approves the result. Avoid silent truncation.

**Regression checks:** 100/101/200 templates, 30/31 headings, nonempty content in the final field, existing-library merge limits, and atomic failure with no changes to the current library or report.

### A07 — The documented double-click edit action mutates the report

**Evidence:** Each macro button has both `onclick = () => insert(m)` and `ondblclick = () => openMacro(i)` in `render()` (`src/core/editor.js:109`). The UI advertises double-clicking to edit (`src/app.html:14`).

**Reproduction:** Focus an empty findings field and double-click the default `re` macro. The edit dialog opens, but the field already contains **`rechtsrechts`**.

**Impact:** Editing a macro can unexpectedly insert clinical wording twice into the active report. Cancelling the dialog does not undo those insertions.

**Suggested change:** Use the existing explicit Edit button as the editing route and reconcile the hint/interaction design. If double-click editing remains supported, ensure its preceding click events do not insert text. Avoid adding a noticeable delay to ordinary macro insertion without considering dictation speed.

**Regression checks:** Single-click insertion occurs once; the supported edit gesture changes no report text; cancelling macro editing leaves the report unchanged; keyboard activation remains usable.

### A08 — The inline diff no longer preserves whitespace

**Evidence:** The whitespace-preservation rule is scoped to `.ai-panel .diff-body` (`src/styles/ai.css:24`). New inline suggestion cards are under `.ai-inline`, outside that ancestor. The replacement rule at `src/styles/material.css:217` restores size and spacing but not `white-space` or long-token wrapping.

**Reproduction:** Generate a multiline suggestion containing an added blank paragraph. The diff's computed `white-space` and `overflow-wrap` are both `normal`; its rendered `innerText` flattens the paragraphs into one line even though its text nodes contain newlines.

**Impact:** The review display does not faithfully represent formatting changes. The underlying proposed/applied text retains its newlines; this finding concerns review fidelity, not an observed alteration of applied text.

**Suggested change:** Apply whitespace preservation and safe wrapping to the inline diff selector in the M3 adaptation layer.

**Regression checks:** Paragraph additions/removals, whitespace-only revisions, repeated spaces, lists, and long unbroken text on a narrow viewport. Check rendered behavior, not only diff token arrays.

### A09 — Model discovery can update the wrong connection

**Evidence:** `loadModels()` reads the endpoint before awaiting the request, then changes the shared model list and possibly selects its first model without checking whether the provider/endpoint changed (`src/ai/panel.js:400–409`). Unlike model-folder loading, it has no revision ticket.

**Reproduction:** Hold the automatic LM Studio `/models` response. Switch to an OpenAI-compatible provider and a different endpoint while its model field is empty. Release the old response. The active compatible profile now contains the old LM Studio model ID.

**Impact:** A stale background request silently changes another connection's configuration, potentially causing a later report request to target an unintended model ID. No report is sent by the model-list request itself.

**Suggested change:** Associate discovery with a captured provider, normalized endpoint, and request generation. Abort or ignore obsolete results, preserve user-entered model changes, and bound the discovery duration.

**Regression checks:** Provider switch, endpoint edit, two discovery requests finishing in reverse order, manual model entry during loading, timeout, and cancellation.

## Suggested order of work

1. **Protect report integrity:** A01 and A02, with focused regression tests. Preserve draft-saving opt-out and explicit application decisions.
2. **Make async ownership explicit:** A03, A04, and A09. Use lifecycle tickets/generations consistently and test delayed completion deliberately.
3. **Preserve library and editing intent:** A05, A06, A07, and A08. Make imports atomic, enforce limits at creation, and verify the rendered diff.
4. **Harden and document:** shared output bounds, keyboard behavior, accurate storage documentation, and portable test execution.
5. **Refactor only after the behavior is covered:** a dedicated formatting-only milestone followed by small module extractions. Retain byte-exact GGUF tests and the clinical invariants throughout.

No new framework, bundler, database, core runtime dependency, or broad redesign is needed to address these findings.

## Scope and verification limits

The audit covered source-level review of editor/storage/settings, AI contracts/providers/UI/local runners, launcher, build/release scripts, design/accessibility behavior, documentation, and targeted builder-state/preview boundaries. All existing engine and browser suites were exercised, including the clinical regression cases. It was not an exhaustive proof over every clinical finding combination.

Testing used synthetic text, synthetic keys, intercepted provider requests, and injected model runtimes. No real patient data, credentials, model downloads, paid AI requests, or live AI endpoints were used. No dependency installation, push, tag, publication, or commit was performed. Pre-existing `.codex/` content was left alone.

Windows with Node **v26.13.0** and Chromium **153.0.8010.12** was exercised. Firefox/WebKit, assistive technology, native Fluency Direct integration, real GPU/CPU inference, fresh upstream vulnerability databases, and independent clinical validation remain outside this audit. Detailed test outcomes and reproduction evidence are in [the verification report](AUDIT-2026-11-15-VERIFICATION.md).
